# 1. Record architecture decisions

Date: 2026-10-01 · Status: Accepted

## Context

This is a portfolio project; reviewers should be able to see why it was built the way it was, not just what was built.

## Decision

Record significant decisions as short ADRs in `docs/adr/`, using the context / decision / consequences format.

## Consequences

Every choice that would be hard to reverse or that a reviewer might question gets a file. ADRs are cheap to write and stay next to the code they explain.
